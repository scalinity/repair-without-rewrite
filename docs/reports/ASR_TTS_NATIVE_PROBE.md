### Pinned ASR implementation limitations

These receipts measure the **declared Parakeet-MLX 0.5.2 path on these development clips**; its source quality failed, and numerical equivalence to NVIDIA's original Nemo implementation was not established. BF16 is proven for the stored weights; it is not a claim that every operator/activation uses BF16. Static inspection shows that the package's audio loader returns FP32 waveform data despite the dtype argument, and log-mel preprocessing returns that input dtype. Its spectral reduction adds absolute real/imaginary components and then applies the configured magnitude power; for power two that is `(abs(real)+abs(imag))²`, which differs from the usual `real²+imag²`. The package also declares a dither configuration field that this inspected log-mel path does not consume. These differences join the strided-frame geometry defect above as unqualified preprocessing behavior; they do not independently establish the cause of the observed NaNs. No independent Nemo preprocessor/output parity was run, no dependency was patched, and no vendor-original equality claim is supported by these timing receipts.

The failed source/implementation result remains useful as reproducible cost and source-error evidence for the exact pinned channel. Ordinary source-error counts under both PC policies are separate evidence, not a source-model quality or held-out final result. Broader recognizer qualification, a second recognizer, longer/representative input distributions, acoustic construction/screening yield and study feasibility remain outstanding.
