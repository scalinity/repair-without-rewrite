4. PHASE A — INDEPENDENT SCORER ORACLE FIRST
==================================================

Implement scorer correctness BEFORE relying on it for model decisions.

Keep the tiny independent oracle structurally separate from the optimized scorer implementation.

The oracle and production scorer must not merely call the same core traceback routine.

Start with finite obvious fixtures covering at least:

1. R=S=O identity.
2. Source wrong → output exactly correct.
3. Source correct → output substitution error.
4. Source insertion correctly deleted.
5. New output insertion.
6. Source deletion repaired by output insertion.
7. Wrong → different wrong.
8. Leading insertion.
9. Trailing insertion.
10. Repeated-token alignment ambiguity.
11. Multiple optimal R/S alignments.
12. Multiple optimal R/O alignments.
13. Compatible triple paths whose S/O projection is not an unrestricted pairwise optimum.
14. Empty R/S/O combinations.
15. Legitimate empty reference.
16. Missing/invalid output.
17. Completed empty output.
18. Capped/truncated valid prefix.
19. Unicode NFC/case-fold policy fixtures.
20. Apostrophe/hyphen scanner policy fixtures.

Required invariant for raw counts where defined:

repair - introduced = d(R,S) - d(R,O)

Implement:
- exact Levenshtein distance oracle;
- R/S and R/O optimal path/lattice construction;
- compatible triple-path development scorer;
- all conditional-optimum tie handling;
- repair/introduced minima and maxima;
- ambiguity/coverage status;
- invalid-output mapping;
- fixed source-defined denominators.

Then add:

A. Exhaustive tiny enumeration
- all R/S/O triples over alphabet {a,b}
- lengths 0 through 3
- expected count: 3,375 triples
- verify distance, compatibility, extrema, invariants, deterministic serialization.

B. Property-based testing
- initial 10,000 trials
- fixed seed from v1.2 unless an implementation reason requires a prospective recorded change.

C. Metamorphic testing
At minimum:
- corpus duplication leaves ratios unchanged;
- case order leaves results unchanged;
- identity output cannot create raw repair/introduction;
- replacing a uniquely correct source token with a wrong token increases introduced error as expected;
- repairing a uniquely wrong source token to reference increases repair;
- equivalent serialization round trips;
- candidate output cannot alter source-defined eligibility.

D. Independent parity
- independent program structure;
- standard edit-distance library only validates ordinary distance unless it actually matches the joint objective;
- prepare the 500-development-triple parity harness, but do not consume sealed final data.

E. Computational qualification
Measure:
- scorer throughput,
- peak joint states,
- edge counts,
- cap frequency,
- ambiguity rate,
- bound widths,
- memory.

No manual ambiguity rescue is allowed.

Deliverable:
docs/reports/SCORER_FOUNDATION_REPORT.md

It must contain:
